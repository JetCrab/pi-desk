# 使用隔离工作区

项目有专用隔离开发 Skill 时，先按它的项目流程准备和运行；这里仅说明通用工作区命令。

| 场景                 | 命令                                                    | 结果                                                              |
| -------------------- | ------------------------------------------------------- | ----------------------------------------------------------------- |
| 开始新需求           | `workspace acquire`，提供 definition 和简短 requirement | 返回已初始化的 root 和本次 workspaceRef；插件自行决定复用还是新建 |
| 接手已有需求         | `workspace use`，提供完整 workspaceRef                  | 在当前会话选中该工作区；先用 `info` 核对需求和目录                |
| 查看当前工作区及命令 | `workspace info`                                        | 获取当前状态、可执行命令及其作用和参数                            |
| 执行项目命令         | `workspace run`，提供当前命令及所需参数                 | 执行 `info` 中声明的命令；以实际结果和日志判断完成情况            |
| 查看整个工作区池     | `workspace list`                                        | 仅在用户要求查看工作区池时调用                                    |
| 取消当前选择         | `workspace use`，不传 workspace                         | 仅清除当前会话选择，不释放工作区                                  |

执行项目命令前先用 `info` 确认命令及参数。会话 cwd 不会随工作区切换，操作源码时显式使用返回的 root 路径；已占用工作区始终使用当前完整 workspaceRef。清理或丢弃内容的命令须由用户明确要求，失败时报告错误与日志，不猜测状态。
