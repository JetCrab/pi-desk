# 配置远程调试

项目配置保存在 `<项目>/.pi/remote_debug.yaml`，随项目移动。端口范围和登记在当前 Pi AgentDir 的 `pi-desk-remote-debug-ports.json`；登记允许重复，仅在新分配时优先避开。

## 配置流程

1. 读取项目现有配置和实际启动脚本，确认启动目录、命令、本机入口及后端端口。已有端口优先保留。
2. 将下文 CLI 路径相对本 Skill 目录解析成绝对路径，执行 `show` 查看范围与登记；已有项目先执行 `sync <项目绝对路径>`。也可在“设置 → 远程调试 → 端口登记”查看完整项目路径与登记。
3. 准备包含项目全部启动项的 JSON，使用 `save` 保存。数字保留指定端口，`null` 在保存时自动分配。`description` 写一句面向使用者的用途简述。
4. 核对返回的实际端口。**分配不会改写启动命令或项目开发配置**：若新分配端口不同于项目默认端口，按项目支持的参数或配置调整实际监听，再保存一致的配置。不要推测框架的传参方式。
5. 检查每个路由目标均有相应服务由启动命令负责启动。报告启动项、本地地址、分配的公网端口及必要的启动前提；只有隧道实际就绪后才能报告远程地址可用。

## 配置 CLI

脚本：`../../dist/l4-remote-debug-config-cli.js`。

```text
node <脚本绝对路径> show
node <脚本绝对路径> sync <项目绝对路径> [更多项目绝对路径...]
node <脚本绝对路径> save <项目绝对路径> <配置JSON绝对路径>
node <脚本绝对路径> ranges <范围JSON绝对路径>
```

`save` 接收 `{ "profiles": [...] }`，每项为：

```json
{
  "name": "web",
  "description": "网站与接口联调",
  "command": "pnpm dev",
  "entryPort": null,
  "publicPort": null,
  "routes": []
}
```

路由项格式为 `{ "path": "/api", "targetPort": 端口数字或null }`。多条路径共用后端时填写相同数字，不重复申请端口。`save` 替换项目全部启动项，编辑前保留未修改项。CLI 和设置页使用同一存储与分配逻辑，不手工修改全局登记 JSON。

范围 JSON 为 `{ "localRange": { "start": 数字, "end": 数字 }, "publicRange": { "start": 数字, "end": 数字 } }`。调整范围不会改动既有项目端口；没有空位时扩大范围或明确选用已有端口。

## 路由与访问

- 公网入口按路径转发：未匹配路径进入 `entryPort`，匹配路径进入对应目标端口；长路径优先，HTTP/WebSocket 一致，保留完整路径。
- 路由不负责启动服务，也不改写浏览器中写死的 `localhost`。前端通过 `/api` 等相对路径访问后端。
- 本地地址指运行项目的电脑。其他设备使用公网地址；直接访问本机入口不经过插件路由。
- Tunnel 连接信息沿用 Pi Desk 桌面壳的“隧道连接”设置，不在项目中复制密钥。
- 登记重复可以保存；启动时实际占用仍会失败，不停止其他项目或自动改号。
