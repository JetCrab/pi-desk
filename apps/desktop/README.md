# Pi Desk Desktop

Tauri 桌面客户端，共用 React 前端、服务安装/更新、网页窗口和隧道能力。

- Windows：保留现有 32 位构建入口，使用 `pnpm check` 检查 Rust。首次准备与 macOS 共用精简界面，按 Node.js、Git Bash、Pi、Pi Desk 展示实际状态；仅在用户开始安装缺少组件时由官方安装器按需请求管理员确认，不要求整个应用以管理员身份运行。正常授权及安装等待不显示失败；取消准备时等待已启动的系统安装事务结束，再停止后续步骤。手动路径、MSI 和下载设置收在“安装选项”。
- macOS 11+：在 macOS 使用 `pnpm build:mac` 构建 Apple Silicon + Intel 通用应用；云构建须安装两个 Rust target，并为前端及 Rust 产物指定独立临时目录。图标可由现有 `src-tauri/icons/icon.png` 生成。
- macOS 自动准备从 Node.js 官方下载 22.22.2 对应架构归档并核对 SHA256，Node 和 npm 全局包使用应用自有目录，不修改系统 PATH。也可选择已有 Node.js 安装目录或其 `bin` 目录。Git 使用已有安装；缺少 Command Line Tools 时，仅在用户开始准备后请求系统安装，等待期间保持准备状态，检测完成后自动继续，无需重新安装或手动重检。取消准备只停止等待，不关闭 macOS 安装器。不预先申请目录、照片或其他与安装无关的隐私权限。

本机服务优先复用应用环境中可执行且版本兼容的 Node.js/npm，不要求固定安装目录。缺少环境时可点击“安装并打开”下载准备，或在“安装选项”中选择已有 Node.js 安装目录（目录内含 `node` / `node.exe` 或 `bin/` 下的同名程序）。仅访问远程地址不需要 Node.js。桌面应用与终端可能继承不同的 PATH；检测失败不代表机器没有安装 Node.js。

安装依赖后使用 `pnpm typecheck:web` 检查前端。原生安装包及交互须在对应平台单独构建验证；当前 macOS 配置采用 ad-hoc 签名，无 Developer ID、无公证，非 App Store 分发。

## TCP 隧道

控制中心的“远程访问”分为“本机共享”和“远端连接”，不依赖网址书签。首次在“设置”保存控制服务 `http://` 地址与 64 位十六进制控制密钥。

- 在“本机共享”添加本机端口，目标固定为 `127.0.0.1:<本机端口>`。按需开启公网访问并填写公网端口；否则只供客户端访问。主列表可复制连接信息，启停、编辑和删除位于更多菜单，统计位于连接详情。
- 接收方使用同一控制服务和密钥，在“远端连接”粘贴 `pidesk-tcp://<提供端标识>:<目标端口>`，选择固定本地端口后连接。连接信息不包含密钥或token，不注册系统URL协议。业务程序访问 `127.0.0.1:<本地端口>`；占用时报错，不自动换号，也不启动提供端业务服务。
- 已配置的本机HTTP(S)网址与共享端口匹配时，提供打开网页和复制公网链接；普通TCP端口只复制地址，不推断为HTTP。
- `auto` 允许先经中继建连再直连；`relay-only` 关闭访问端直接 IP 传输，只经 relay。界面显示真实路径，自动策略不保证直连。切换策略会中断本进程访问端的现有 TCP 并重建，本地端口不变；本机提供端与其他独立 CLI 不受影响。
- 活动 TCP 是已建立的业务转发流，不是请求数或人数。活动接入端是有活动流的不同 iroh 对端；多个公网访问者可能共用一个网关对端。桌面仅显示本进程提供端统计，不包含插件启动的独立 CLI。

首次启用时生成并保存提供端私钥，提供端标识从私钥推导。配置保存在 `config.json` 的顶层 `tunnel`：`publications` 保存发布项，`forwards` 保存本地映射，`mode` 保存访问策略；网址 `targets` 只负责网页及托管服务。删除书签不会删除独立发布。

旧 `targets[].tunnel` 按 URL 的有效本机端口读取转换，保留公网端口和启用状态。同一本机端口出现冲突设置时报告具体记录并保留原文件，不静默覆盖；升级前应备份配置。

首次隧道 owner 启动前，保存连接设置即可用于首次连接。owner 启动后再改控制地址或密钥，界面提示“退出并重启应用后生效”；新增端口、恢复和模式切换仍使用已捕获的连接设置，停止再启用单个端口不会刷新设置。独立 CLI 则读取其启动时最新保存的配置，并使用临时身份，不复用桌面私钥。

控制服务长期失联时，提供端会在本地授权截止前撤销该端口并关闭流；即使直连数据仍通也不无限维持授权。截止点不晚于最近一次成功 open/status 请求发出后 30 秒。

隧道只转发 TCP，不改写 HTTP Host、Cookie、TLS/SNI 或 WebSocket Origin。服务端、桌面端须同步升级到 v2；旧 v1/Noise 协议不自动降级。切换在维护窗口进行，原有 TCP 会断开，回退使用备份的旧制品和旧配置。

插件仍直接调用桌面无头CLI，不依赖打开页面或在页面创建共享；页面不接管插件子进程。部署、无头 CLI 的 NDJSON/`--stats` 合同及升级说明见[隧道手册](../tunnel/README.md)。

## macOS 安装

打开 DMG，将 `Pi Desk.app` 拖入 `Applications`，复制完成后从“应用程序”打开 Pi Desk，再推出磁盘映像。Node.js、Pi 和服务包由控制中心按需准备。

覆盖安装前，先在控制中心停止本机服务，再从 Pi Desk 菜单退出应用；关闭窗口不等于退出。Finder 负责复制和替换，不会替用户终止后台服务。应用配置、包和会话保存在应用包之外，拖拽替换不会主动删除这些数据。

`pnpm build:mac` 使用 Tauri 构建 Apple Silicon + Intel 通用 DMG，产物位于 `temp/build/desktop-rust/local/universal-apple-darwin/release/bundle/dmg/`（相对仓库根目录；设置 `CARGO_TARGET_DIR` 时跟随该目录）。Finder 背景和图标位置由 `src-tauri/tauri.macos.conf.json` 配置；修改 `dmg-background.svg` 后须同步生成 `dmg-background.png`。

没有开发者账号也能构建。当前使用 ad-hoc 签名，未进行 Apple 公证；首次打开被系统拦截时，可在“系统设置 → 隐私与安全性”中检查并选择“仍要打开”，具体行为受系统版本和设备策略影响。云端可沿用 `APPLE_SIGNING_IDENTITY` 使用 Developer ID 签名，签名不等于公证。

云端挂载最终 DMG，检查主应用、Applications 链接、Finder 布局资源、版本、双架构和签名。实际拖拽、首次启动及明暗桌面下的 Finder 展示仍须在 macOS 验收。
