在手机、平板或另一台电脑上打开 Pi Desk，继续查看消息和执行任务。项目仍在运行 Pi Desk 的电脑上；其他设备可通过公网地址直接访问，也可在安装桌面端后使用固定本地端口。

两种入口共用 iroh TCP 隧道。公网网关接收普通浏览器或 TCP 程序连接，访问设备无需安装隧道客户端；原生客户端映射则可以直连，不能直连时使用中继。

## 设置访问密码

在运行 Pi Desk 的电脑上，进入「设置 → 登录保护」，设置至少 8 位密码并启用。**远程访问必须先设置密码，并保持登录保护开启。**

访问密码用于登录 Pi Desk；连接密钥用于桌面端访问隧道控制服务，两者不同。

## 准备公网网关与中继

Linux 公网服务器使用同一隧道镜像运行两个容器：

| 服务                               | 作用                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------ |
| gateway（`pi-desk-tunnel-server`） | 控制服务和动态公网 TCP 入口，接收普通程序访问                            |
| `iroh-relay`                       | 在端点不能直连或选择强制中继时，转发端点间的加密数据；不替代公网业务端口 |

按仓库[隧道部署说明](https://github.com/JetCrab/pi-desk/tree/main/apps/tunnel)准备 `.env`、私有 relay TOML 和匹配域名的 TLS 证书，再使用 Docker Compose 启动。镜像内同时提供网关和从固定 iroh 1.4.1 发布 commit 构建的 relay；两个容器通过不同程序入口运行。`PI_DESK_TUNNEL_IMAGE` 指定同一发布版本，旧 v1 镜像不能用于这份配置。

部署者需要准备以下连接信息，容器不会自动生成密钥或 `connection.txt`：

- `PI_DESK_TUNNEL_SERVER_KEY`：64 位十六进制控制密钥，供桌面端填写。
- `PI_DESK_TUNNEL_PUBLIC_HOST`：公网业务主机名或 IP，不带端口。
- `PI_DESK_TUNNEL_IROH_RELAY_URL` 与 `PI_DESK_TUNNEL_IROH_RELAY_TOKEN`：relay 地址和准入 token，后者同时用于 relay 授权。
- `IROH_RELAY_CONFIG_PATH` 与 `IROH_RELAY_CERT_DIR`：Compose 挂载的私有配置文件和证书目录。

两个容器使用 host 网络，部署前核对端口占用。gateway 访问同机 relay 时，需在保留正确 TLS 主机名的前提下经本地 DNS/路由连接，不经 CDN 或公网回流；仅部署在同一台服务器不能保证这一点。

按实际配置在云安全组和服务器防火墙放行：

| 用途                | 示例端口                                    |
| ------------------- | ------------------------------------------- |
| 控制 HTTP           | TCP `7001`，对应 `PI_DESK_TUNNEL_BIND`      |
| relay HTTP/TLS      | TCP `8080` / `8443`，由 relay TOML 设置     |
| relay QUIC 地址发现 | UDP `7842`，示例配置启用；不是 UDP 业务转发 |
| 公网 Pi Desk 入口   | TCP `40333`；多个发布端口需分别放行         |

控制健康接口 `/api/v2/system/health` 只证明控制进程在线，不能代替实际公网或中继数据转发检查。

## 发布本机端口

以下使用文档示例 IP `203.0.113.10` 和端口 `40333`；替换为实际部署值。

1. 在提供端启动本机 Pi Desk，确认本机网址能打开，默认 `http://127.0.0.1:30333/`。
2. 打开桌面「控制中心 → 远程访问 → 设置」，保存控制服务地址（例如 `http://203.0.113.10:7001`）和控制密钥。
3. 在「本机共享 → 共享端口」填写本机端口 `30333`，开启公网访问并填写公网端口 `40333`，点击「开始共享」。显示「共享中」后，可复制公网地址；已配置对应本机网页时，还可直接打开网页或复制链接。
4. 在其他设备的浏览器或 Android 客户端填写 `http://203.0.113.10:40333/`，输入访问密码，发送消息并确认回复实时出现。

公网端口留空时，该发布仅允许原生客户端访问，不生成公网地址。端口发布独立于网址列表；编辑或删除网址书签不删除发布项。多个本机端口分别添加发布，不共用一个公网端口。

## 通过固定本地端口访问

访问电脑安装 Pi Desk 桌面端后，可以通过原生映射连接提供端：

1. 提供端在「本机共享」启用所需端口，点击「复制连接信息」。信息只包含稳定的提供端标识和目标端口，不含密钥。
2. 访问端在「远程访问 → 设置」填写相同控制服务地址和密钥。
3. 在「远端连接 → 添加连接」粘贴连接信息，确认固定本地端口（例如 `50333`），点击「连接」。列表显示实际直连或中继状态。
4. 访问端浏览器打开 `http://127.0.0.1:50333/`。其他 TCP 程序同样连接这个固定本地端口；端口占用时报错，不自动换号。

「自动」策略允许先经中继建连，再尝试直连；自动模式下显示中继也是正常结果，不保证所有网络都能直连。「强制中继」关闭访问端直接 IP 传输，只经 relay。界面按真实连接显示直连、中继或未知，不以所选策略推断路径。

切换策略会中断并重建本进程访问端的现有 TCP，本地端口不变；本机提供端与独立调试 CLI 不受影响。公网浏览器始终经公网网关，即使网关到提供端的内层路径显示直连，也不是浏览器绕过了服务器。

## 连接状态与升级

- **保持在线**：业务服务、提供端、控制网关和所需 relay 需要持续运行；退出提供端桌面应用会中断其远程访问。
- **连接设置**：首次启用隧道前保存即可使用；隧道 owner 已启动后修改控制地址或密钥，须退出并重启应用。仅停止再启用单个端口无效，新增端口、恢复和策略切换仍使用已捕获的连接设置。
- **授权期限**：控制服务长期失联时，提供端不无限维持直连授权；本地截止点不晚于最近一次成功 open/status 请求发出后 30 秒，届时回收该端口的授权和流。
- **计数口径**：活动 TCP 是业务转发流，不是请求数或人数。活动接入端是有活动流的不同 iroh 对端；多个公网访问者可共用一个 gateway 对端。桌面不包含独立 CLI 的统计。
- **传输边界**：iroh 加密端点间数据，但公网浏览器到网关的普通 HTTP 仍未加密。需要 HTTPS 时由业务或入口提供 TLS；隧道不改写 Host、Cookie、Origin 或证书，不承载 UDP 业务。
- **同步升级**：v2 与旧 v1/Noise 不兼容。在维护窗口同步升级服务端与桌面，使用新统计的调试插件还需要支持 `--stats` 的桌面。公网主机和端口不变时，原访问地址可保留，但切换会断开活动 TCP。
- **配置转换与回退**：升级前备份配置与旧制品。旧 `targets[].tunnel` 按 URL 的有效本机端口转换，保留公网端口和启用状态；冲突时报告记录并保留原文件。回退使用外部旧制品及升级前配置，不依赖新程序自动降级。

## 同一局域网访问

两台设备在同一个局域网时，可以不用公网服务器和隧道。先设置访问密码，再让 Pi Desk 监听局域网地址，例如：

```bash
pi-desk start -H 0.0.0.0 -p 6233 --no-open
```

在电脑防火墙放行 TCP `6233`，另一设备打开 `http://电脑的局域网IP:6233/`。不要填写 `0.0.0.0` 或 `127.0.0.1`。

## 连不上时检查

1. 本机业务能否打开，提供端与所需网关、relay 是否仍在运行。
2. 控制地址和密钥是否正确，修改后是否已退出重启；服务端与桌面是否同为 v2。
3. 发布是否就绪，公网主机/端口是否正确，防火墙是否放行实际控制、relay 和业务端口。
4. 是否从正确的共享项复制了连接信息、本地端口是否被占用；详细目标和运行错误从连接详情查看。
5. relay TLS 主机名、证书、准入 token 和同机本地路由是否匹配；自动直连还受 UDP、NAT 和防火墙影响。

忘记访问密码时，查看[密码恢复方法](/docs/faq/#忘记登录密码)。
