# Pi Desk 管理命令

本页说明宿主 `pidesk` 工具及结果语义；其他使用和开发资料见[文档入口](./README.md)。

## 调用管理工具

`pidesk` 是宿主 API 工具，不是任意 Shell。参数是命令 token 数组，不包含 `pidesk` 前缀，也不解析管道、重定向或 Shell 表达式：

```json
{ "args": ["--help"] }
```

当前命令以 `pidesk --help` 为准，各级命令均支持 `--help`，例如 `{ "args": ["plugins", "install", "--help"] }`。

| 查询                  | args                                                     |
| --------------------- | -------------------------------------------------------- |
| 宿主版本              | `["--version"]`                                          |
| 当前宿主环境与目录    | `["info"]`                                               |
| 插件清单与维护状态    | `["plugins", "list"]`                                    |
| 按各插件渠道检查更新  | `["plugins", "list", "--check-updates"]`                 |
| 只检查跟随 dev 的插件 | `["plugins", "list", "--check-updates", "--tag", "dev"]` |
| 插件详情              | `["plugins", "show", "<name>", "--scope", "global"]`     |

`info` 可取得当前 `agentDir`；下文 `<AgentDir>` 表示这个实际目录，不假定默认位置。管理入口只支持全局范围，不支持项目级管理。

## 区分接纳与完成

- `mode: sync`：本次执行已经结束，直接使用返回结果。
- `mode: async`：操作已经接纳，尚未完成；宿主会把最终结果插入本会话并唤醒模型。没有独立工作时结束当前轮，等待最终通知，不轮询、不重复提交。
- 工具报错表示请求失败；已接纳、等待加载或等待重启都不能报告成已生效。
- 批量操作每批返回一条最终汇总，逐项区分成功、未接纳、失败和等待重启；某项失败不代表其余项失败。

## 安装、更新与重载

| 操作                   | args                                                                          |
| ---------------------- | ----------------------------------------------------------------------------- |
| 安装、更新或重装       | `["plugins", "install", "<name>", "--scope", "global"]`                       |
| 批量安装或更新         | `["plugins", "install", "<name-1>", "<name-2>", "--scope", "global"]`         |
| 安装并跟随 dev         | `["plugins", "install", "<name>", "--scope", "global", "--tag", "dev"]`       |
| 安装指定 npm 版本      | `["plugins", "install", "<name>", "--scope", "global", "--version", "1.2.3"]` |
| 重载已安装插件当前代码 | `["plugins", "reload", "<name-1>", "<name-2>", "--scope", "global"]`          |
| 卸载包来源             | `["plugins", "remove", "<name-1>", "<name-2>", "--scope", "global"]`          |

`install` 包含首次安装、更新和重装；目标版本已安装也会重装。`reload` 只重新加载本机现有码，不下载、不修改版本或渠道、不重启宿主，也不重载已有 Pi 会话；它不接受 `--version` 或 `--tag`。

### 本地插件

源码放在 `<AgentDir>/extensions/<name>/`。首次接入用 `install`；修改已安装插件后用 `reload`。有浏览器构建入口时先完成必要编译；原生 TypeScript 与 Pi Desk Node Entry 可由宿主直接加载，不必为本地验证发布 npm 或生成安装包。

命令使用清单或固定目录中的名字，不传自定义路径；单文件扩展使用清单中的名字。本地来源不接受版本或渠道。同名来源冲突时先确认目标，不猜测。

### npm 插件

使用完整 npm 包名，例如 `@example/plugin`，不把版本拼在名字里。多个插件共用一次命令选择的标签或版本。

- 省略版本和标签：新插件默认 `latest`，已有插件沿保存的更新渠道。
- `--tag dev`：安装该标签指向的版本，并保存后续跟随渠道。
- `--version 1.2.3`：只指定本次完整版本，不改变已有渠道；与 `--tag` 互斥，不从版本后缀猜渠道。
- `list --check-updates` 不安装；附加 `--tag dev` 只筛选跟随 dev 的插件，不改变渠道。标签缺失或查询失败报告对应项错误，不回退 `latest`。
- 只调整渠道而不安装：在插件管理界面多选后使用“设置渠道”。

包文件与 Pi `settings.json` 由官方包管理器维护，不手动覆盖安装目录或包声明。`remove` 只卸载管理入口支持的包来源，不附带业务数据清理；裸扩展卸载不在此命令能力中，不以删除源码或新增禁用规则代替包卸载。

## 让已有会话采用当前配置

```json
{ "args": ["session", "reload"] }
```

等同输入框“更多 → 重载 Pi 配置”：保留聊天历史与当前分支，重新加载 Pi 配置、Skills 和本机已安装插件的当前代码，不下载新版本。需要 npm 新版时先 `plugins install`，再按用户需要重载目标会话。

接纳后结束当前轮；宿主等本会话完全空闲后重载，再通知并唤醒本会话。重载可能重建插件内存状态、使缓存失效，配置和工具声明变化也可能影响提示词缓存。

插件管理只等待目标来源必要的在途调用，不冻结常规聊天。完成通知表示包和宿主能力已应用；新建会话使用最新工具配置，已有原生 Pi 会话不自动重载。Node/Browser 替换会重新挂载目标插件界面，旧调用可能失效；结果未知的副作用请求不自动重发。

需要重启时按插件管理界面的维护流程处理，以最终结果为准。
