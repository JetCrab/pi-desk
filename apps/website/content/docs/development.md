把你需要的功能说给 AI，让它参考 SDK 的公开类型声明和已有插件完成开发。Pi Desk SDK 为原生 Pi 工具补充网页界面，也支持独立的界面插件。

## 为什么用插件

- **保留已有工具**：原生 Pi 扩展不用重写，就能补上网页入口和结果展示。
- **少写重复代码**：复用界面组件、文件预览、日志和任务中心，专注自己的功能。
- **按需加载**：界面用到时才加载，减少启动负担。
- **独立更新**：修改插件后加载变更，不必重新打包整个 Pi Desk。

## SDK 能做什么

| 能力               | 怎么用                                                  |
| ------------------ | ------------------------------------------------------- |
| 独立应用、设置页   | 做一个数据看板，或让用户填写插件配置                    |
| 会话侧栏、输入辅助 | 展示当前任务的文件，或在发送消息前选择参数              |
| 聊天结果展示       | 将工具结果显示为清晰的摘要，按需展开详情                |
| 后台任务与日志     | 查看执行进度、日志，并提供停止操作                      |
| 文件预览与通知     | 打开生成的图片、代码、页面，提醒任务完成                |
| 公共界面组件       | 复用按钮、表单、弹窗和 Markdown，跟随宿主主题与显示大小 |

## 交给 AI 开发

GitHub 源码与在线开发文档：**待上线**。

已有本地源码时，让 AI 先读这些文件：

| 阅读顺序   | 文件                                 |
| ---------- | ------------------------------------ |
| SDK 入口   | `plugins/pi-desk-sdk/README.md`      |
| 公共类型   | `plugins/pi-desk-sdk/src/index.ts`   |
| 插件声明   | `plugins/pi-desk-sdk/src/entry.ts`   |
| 浏览器能力 | `plugins/pi-desk-sdk/src/browser.ts` |

可以这样描述需求：

> 请阅读本地 Pi Desk 源码中的 SDK README 和当前版本的公开类型声明，参考功能相近的插件，为我开发【功能描述】。涉及界面时，先向我取得对应版本的 UI 标准及分册并完整阅读。完成构建、加载，并验证实际功能。

涉及会话能力时，可继续查阅 `plugins/pi-desk-sdk/src/session.ts`；已安装的 npm SDK 以该版本 `package.json` 导出的 TypeScript 声明为准。

## 修改后怎么生效

让 AI 完成插件构建后，在“设置 → 插件”点击“加载变更”。界面和插件服务可单独更新；若修改了聊天工具，再在会话空闲时“重载 Pi 配置”。出现重启提示时按提示操作，更新前先结束相关任务。

安装现成插件见[安装与使用插件](/docs/plugins/)。
