手机、平板或另一台电脑都能访问同一个 Pi Desk 工作台。项目和任务仍在原来的电脑上运行，远程设备只是打开它的网页。

## 先准备公网入口

在 Linux x86_64 公网服务器上安装 Docker、Docker Compose、Python 3 和 curl。将域名的 A 记录指向服务器，确保没有 AAAA 记录；公网 TCP `443` 必须直达服务器，不能被其他服务或 CDN 占用。

替换命令中的域名和证书联系邮箱，运行：

```bash
(set -o pipefail; curl -fsSL https://raw.githubusercontent.com/JetCrab/pi-desk/main/apps/tunnel/deploy/init.py | sudo python3 - --domain tunnel.example.com --email admin@example.com --image ghcr.io/jetcrab/pi-desk-tunnel:1.1.2)
```

脚本使用镜像启动网关和 relay，自动生成密钥、申请并续期 relay 证书。首次申请证书表示接受 Let's Encrypt 服务条款。配置保存在 `/home/apps/pi-desk-tunnel/`，重复运行保留原配置。

在服务器安全组和防火墙放行 TCP `443`、`7001`、UDP `7842`，以及实际使用的公网业务 TCP 端口（例如 `40333`）。脚本不会修改防火墙。详情见[隧道部署说明](https://github.com/JetCrab/pi-desk/tree/main/apps/tunnel#部署网关与-relay)。

启动后，使用终端显示的**控制服务地址和控制密钥**配置桌面端；手机访问不需要控制密钥。脚本检查本机服务和证书后，仍需实际从其他设备访问，确认公网转发可用。

## 设置密码与桌面连接

<!-- devices-demo -->

1. 在运行 Pi Desk 的电脑上，打开工作台「设置 → 登录保护」。设置密码并点击「启用登录保护」；可用「生成密码」。密码须为 12–64 个字符，包含大写、小写、数字、符号中的至少三类。保存后，所有设备需重新登录。
2. 打开桌面「控制中心 → 远程访问 → 设置」，在「服务器设置」填写控制服务的 `http://` 地址和控制密钥，点击「保存设置」。这里不是手机要打开的网页地址。
3. 在「本机共享 → 共享端口」填写 Pi Desk 的本机端口（默认 `30333`），开启公网访问，填写服务器上可用的公网端口，例如 `40333`，点击「开始共享」。
4. 等待显示「共享中」，复制公网链接或地址。在手机浏览器打开该地址，或将网址填入 Android 客户端，再用第 1 步的密码登录。发送一条消息，确认回复能实时出现。

共享端口与桌面已配置的本机 HTTP(S) 网址匹配时，才提供「打开网页／复制公网链接」；普通 TCP 端口只提供地址。端口按实际配置填写，演示中的地址不能访问。

## 选择适合的访问方式

| 入口           | 什么时候用                                        | 实际连接                                                    |
| -------------- | ------------------------------------------------- | ----------------------------------------------------------- |
| 公网访问       | 手机浏览器、Android 客户端，或未装桌面端的设备    | 公网地址 → 网关 → 运行 Pi Desk 的电脑；访问端无需隧道客户端 |
| 原生客户端映射 | 另一台装有 Pi Desk 桌面端的电脑，需要固定本地端口 | 本地端口 → 提供端；可直连，不能直连时走 relay               |
| 局域网访问     | 两台设备在同一局域网                              | 设备直接访问电脑的局域网地址，无需公网服务器和隧道          |

**原生客户端映射**：提供端共享本机端口后点击「复制连接信息」。访问端桌面配置相同的服务器地址和控制密钥，再到「远端连接 → 添加连接」粘贴信息，填写固定本地端口（如 `50333`），点击「连接」。浏览器打开 `http://127.0.0.1:50333/`。不需要公网入口时，共享项可不开启公网访问。

「自动」策略会尝试直连，显示中继也是正常结果；「仅中继」不尝试直接 IP 传输。切换策略会重建访问端连接，本地端口不变。公网浏览器始终经过网关，不会因此变成浏览器直连电脑。

**局域网访问**：先启用登录保护，再让 Pi Desk 监听局域网地址，例如：

```bash
pi-desk start -H 0.0.0.0 -p 6233 --no-open
```

电脑防火墙放行 TCP `6233`，其他设备打开 `http://电脑的局域网IP:6233/`。不要把 `0.0.0.0` 或 `127.0.0.1` 当成另一设备的访问地址。

## 保持可用与安全

- **保持在线**：Pi Desk 服务、提供端桌面应用、网关与所需 relay 要持续运行。退出提供端桌面应用会中断远程访问。
- **保护入口**：远程访问前先启用登录保护，并保持开启。访问密码用于登录工作台；控制密钥用于可信桌面端连接隧道，不要发给普通网页访问者。
- **传输加密**：iroh 加密隧道端点间的数据，但公网地址使用普通 HTTP 时，浏览器到网关这一段未加密。公网长期使用应配置 HTTPS；隧道不会自动为业务网页添加 TLS。
- **更改连接**：首次启用隧道前保存设置即可使用。隧道已启动后再改服务器地址或密钥，需要退出并重启桌面应用，仅停止再共享端口无效。

## 连不上时检查

1. 先确认电脑上的 Pi Desk 网页能打开，桌面共享项已显示「共享中」。
2. 核对控制地址、密钥和公网地址，检查服务器安全组与防火墙是否放行实际端口；修改连接设置后重启桌面应用。
3. 从共享项的「连接详情」查看错误。网关与桌面须使用兼容的 v2 版本；relay 的域名、TLS 证书和配置按[部署说明](https://github.com/JetCrab/pi-desk/tree/main/apps/tunnel)核对。仅容器运行或健康检查成功不代表业务访问成功。
4. 原生映射还需检查连接信息和固定本地端口占用；端口被占用时不会自动换号。

忘记访问密码时，查看[密码恢复方法](/docs/faq/#忘记登录密码)。
