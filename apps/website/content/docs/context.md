上下文管理插件可以手动或自动忽略较早的思考和工具结果正文。你的消息与助手已经写出的文字继续保留，后续请求少带一些旧过程。

## 它是怎么工作的

**聊天记录**是保存下来的完整历史，**上下文**是这一次发送给模型的内容。插件在发送前处理上下文，不改写原始聊天记录。

<!-- context-principle -->

较早的工具结果正文会换成简要调用记录，需要原始结果时，助手可以按需查回。近期过程按设置保留，已识别的 Skill 读取也会受到保护。

因此，它不只是把用量数字变小：你可以继续沿用已有要求和文字结论，又不必让模型每次都携带全部旧过程。**忽略不是生成摘要的“压缩”**，两种操作可以配合使用。

## 试一次上下文忽略

先[安装插件](/docs/plugins/#下载安装) `@jetcrab/pi-desk-ctx`，并按安装完成后的提示加载。已有会话需要更新工具时，在空闲后执行“更多 → 重载 Pi 配置”。

从工作台打开要继续的会话，在输入框底部找到**附件图标右侧的圆环**。电脑上将鼠标移到圆环，手机上轻点圆环，即可展开用量详情。

<!-- context-usage -->

1. **查看用量**：关注“可忽略”和“忽略后预计保留”，判断这次能腾出多少空间。
2. **点击“忽略”**：等待当前回复结束后操作；没有可忽略内容时，按钮不可用。
3. **继续对话**：占用更新后，正常发送下一条要求即可，不需要新建会话。

## 让它自动处理

打开 **设置 → 插件设置 → 上下文忽略**。开启“自动忽略”后，插件会在合适时机检查规则，满足条件时处理旧过程。

<!-- context-settings -->

图中的规则表示：当前占用至少 **280k**，**并且**忽略后预计不超过 **50k**，才会触发。如果预计仍需保留 90k，这条规则不会执行。添加多条规则时，满足其中一条即可。

这里使用 400k 容量模型举例。请按实际模型容量选择范围和调整阈值，不要将这一组数值直接用于所有模型。界面中的 **1k = 1,000 tokens**。

### 按需要调整

- **想多保留近期细节**：适当增加“最近对话轮数”和“过程用量上限”。两项共同生效；设置 3 轮，不代表这 3 轮的全部过程都会原样保留。
- **任务进行中也需要整理**：在高级设置中启用“任务中记录进展”。达到设置用量并满足忽略条件后，插件会请助手先补充必要进展，再处理旧过程。
- **希望回到初始配置**：点击“恢复推荐”，检查后再点击“保存”。修改配置后，后续新一轮任务会读取新设置。

## 使用时记住

- **占用是估算，不是账单。** “已忽略”也不是累计节省量；实际输入成本还受模型、缓存和计费方式影响。
- **历史保留，不等于每次全部发送。** 被忽略的旧过程不再自动进入后续请求；历史工具结果可按需查回，但没有“一键恢复全部上下文”的入口。
