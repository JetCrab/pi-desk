<!-- remote-debug-effect -->

远程调试把本机项目的开发网页临时开放给其他设备，方便用手机检查布局和交互。访问的是**项目页面，不是 Pi Desk 聊天界面**；它不负责聊天消息同步，也不是生产部署。

## 先准备桌面隧道与项目

先[安装插件](/docs/plugins/#下载安装) `@jetcrab/pi-desk-remote-debug`，按提示加载。公网调试依赖**同机 Pi Desk 桌面端托管服务**及已配置的[桌面隧道连接](/docs/devices/#配置桌面端)，平台以桌面端实际支持为准。手机只是访问页面，不能代替托管主机。插件不附带或自动下载独立隧道程序。

项目须能在托管主机运行启动命令；Windows 使用 `bash.exe`，其他平台使用系统 Shell，项目依赖也要先准备好。在 Pi Desk 打开该项目的会话，让应用发现项目目录。

## 配置启动项与端口

项目启动项放在项目根目录的 `.pi/remote_debug.yaml`，可由助手按实际项目准备。应用读取这些启动项，**没有项目配置编辑表单**。以下仅是已安装 Vite 项目的最小格式示例，命令和端口都需按实际情况调整：

```yaml
version: 1
profiles:
  web-preview:
    command: pnpm exec vite --host 127.0.0.1 --port 43120 --strictPort
    entryPort: 43120
    publicPort: 11020
    routes: {}
```

`entryPort` 是项目实际监听的本地入口，必须与命令一致；`publicPort` 是隧道开放的公网端口。需要将 `/api` 等路径转给另一个本地服务时，才增加 `routes`，转发保留原路径；不要配置 `/` 路由。底层网关临时端口由插件处理，无需填写。示例端口不是可直接使用的登记，请先核对占用及隧道服务器允许范围。

<!-- remote-debug-config -->

全局入口是 **设置 → 插件设置 → 远程调试**：“连接”只展示地址，须在桌面端修改；“端口分配”设置自动分配范围，默认本机 43000–43999、公网 11001–11099；“端口登记”用于查归属。保存范围不会改写现有启动项；移除登记不删除项目配置，下次发现项目仍会登记。

## 启动、访问与停止

<!-- remote-debug-demo -->

1. 从工作台左侧打开 **远程调试**，选择项目和启动项，用“详情”核对配置命令、项目目录及路由；暂无启动项时先准备配置，再“刷新”。
2. 点击“启动”。主机运行项目命令，等待本地入口，再启动网关与隧道。出现“运行中”和远程地址后，其他设备才使用该地址；它不是电脑的 `127.0.0.1` 地址。
3. 展开“详情 → 查看日志”排查命令与隧道过程。结束测试后点击“停止”，等待“已停止”；本地、远程地址会撤下，原启动项保留，可“重新启动”。

运行状态不保证网页功能正确，仍需实际访问验证。失败时核对命令、端口冲突和桌面连接，并查看日志，不把启动请求成功当成页面就绪。临时开放只用于需要暴露的测试页面，不上传凭据或私人数据。

全部演示命令、网络与地址均为示意，未启动服务或连接隧道；`example.invalid` 地址不能用于实际访问。
