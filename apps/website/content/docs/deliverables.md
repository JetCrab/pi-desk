<!-- deliverables-effect -->

当助手完成报告、页面、图片或一组文件时，让它把需要你查看、验收的文件或文件夹登记为交付物。结果集中在当前会话的侧栏中，不用再从一长串对话里找文件路径。

## 它是怎么工作的

助手先完成交付内容，再调用 `deliverable` 登记标题和路径。插件校验路径对应的文件或文件夹真实存在，自动识别类型，把这次登记保留在会话记录中。

<!-- deliverables-principle -->

**它不会自动搜集所有文件，也不是云盘。** 登记的是文件引用，不会复制一份备份。普通源码修改、中间文件和不能预览的文件，不应当作最终交付登记。

## 从完成文件到集中预览

先[安装插件](/docs/plugins/#下载安装) `@jetcrab/pi-desk-deliverables`，按提示加载；已有会话需要更新工具时，在空闲后执行“更多 → 重载 Pi 配置”。

告诉助手要交付什么，并要求完成后登记。下面以假项目“轻舟”的检查报告、任务总览 HTML 和封面图片为例；文件、消息和预览内容均为示意，不创建真实文件。

<!-- deliverables-usage -->

1. **确认已经完成**：在对话中查看助手的完成说明与 `deliverable` 登记结果，不是让插件自行扫描项目。
2. **找到交付入口**：保持要查看的会话为当前会话，在左侧栏顶部找到“交付物”文件图标。手机上先展开侧栏，再选择同一入口。
3. **选择交付物预览**：清单显示标题和路径，最新登记排在最前。点击文件打开独立文件预览；点击文件夹打开项目预览，可以浏览目录并选择文件查看。看完关闭，回到清单或继续对话，会话工作目录不变。

侧栏较窄、入口较多时，顶部图标区域可以横向滚动。清单只展示**当前会话分支**的登记，不会把所有项目的文件混在一起。

## 登记时指定什么

交付物**没有独立设置页**。助手每次传入 `items` 数组，每项只需要 `path` 和 `title`，一次可以登记 1–20 个文件或文件夹。

<!-- deliverables-config -->

`path` 支持服务端绝对路径或相对当前会话工作目录的路径，包括 `../`；`.` 表示当前目录，不能填外部网址。`title` 是给你看的标题，长度为 1–40 个字符，尽量简短。

一次登记中的路径都要通过校验；有文件或文件夹不存在，这次登记不会成功，让助手修正后再登记。

## 预览与保留范围

- **登记不等于支持任意格式。** 插件不按扩展名限制登记，实际能否显示由宿主预览决定。常用场景是 HTML、UTF-8 文本或代码，以及 PNG、JPEG、WebP、GIF 图片；不要把它当作 PDF、Office 或压缩包的通用阅读器。
- **HTML 预览不是发布网站。** 独立窗口展示项目文件，不会生成公开访问地址，也不替你部署服务。
- **重复路径不会自动去重。** 再次登记同一路径会保留另一条记录，而不是覆盖前一次交付；这些记录也不是文件版本快照。
- **文件夹不是内容快照。** 只登记目录路径，不递归登记里面的文件；项目预览读取目录当前内容，普通文件夹也能打开，不要求是 Git 仓库。
- **原路径仍需存在。** 后来移走或删除文件或文件夹，清单不会自动变成备份，预览可能失败。恢复原路径的内容，或让助手登记新的有效路径。
- **复制与系统打开。** 文件和文件夹的右键菜单都可复制地址；文件另有“打开所在文件夹”，目录条目通过点击打开 Pi Desk 项目预览。
